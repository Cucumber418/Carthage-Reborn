# 迦太基重生 Carthage Reborn

**简体中文** | [English](README.en.md)

维多利亚 3 模组。1836 年，突尼斯被一个刚刚复兴的布匿民族国家取代：保守而好战的元老们暂时掌握权力，国际社会尚未承认这个国家。它要在汉诺派与巴卡派的斗争中决定自己的道路，复兴布匿文化，并可能重建汉尼拔时代的版图。

- 当前版本：1.2.9
- 适用版本：1.15.*
- 文案语言：简体中文、英文，内置于同一模组，跟随游戏语言自动选择；两种语言各覆盖全部 1,098 个文本键，包含游戏概念、动态地名及国名覆盖。
- 创意工坊介绍：[中文](docs/workshop_description.txt) / [English](docs/workshop_description_english.txt)（Steam 的 BBCode 格式）
- 模组命名空间：`crb`（新增内容使用 `crb_`、`law_crb_`、`company_crb_` 等标识，国家代码与覆盖原版的条目除外）
- 当前内容：7 条日志、2 项决议、74 个事件定义、1 家特色公司、13 个可建立的附庸国家，以及 1 首特色背景音乐

## ⚠️ 制作规范（最高优先级）

**本模组的一切游戏内容，包括文案、术语、数值、美术，都必须与原版维多利亚 3 的风格保持一致。** 玩家在游戏里看到的任何东西，都不应该让人感觉"这是模组加的"。所有新内容在提交前都要对照原版文件检查。

### 文案与语言

- **术语**：一律使用原版简体中文的官方译名，例如"利益集团""日志""影响力""合法性""鼓动者""政治运动""小市民""国教"等。原版已有的概念不另起新译名。
- **文风**：事件、日志、决议的描述沿用原版的叙事口吻，偏书面、克制、带一点历史感，不用网络用语、现代口语和过于煽情的表达。
- **事件正文**：大字正文和引语只交代世界中的背景、人物与冲突。恶名、奖励数值、解锁通知、触发条件和操作规则放在选项效果或悬停提示中，不写成正文；历史年代与故事中经过的时间可以保留。
- **篇幅**：标题、描述、选项的长度与原版同类内容相当。事件选项保持原版的简短风格。
- **格式**：变量、颜色、图标、超链接概念等写法照搬原版（如 `$VALUE|+=$`、`#bold ... #!`、`@money!`、`[concept_xxx]`），不自创格式。
- **人名地名**：音译参照原版和通行的中文译名习惯；历史上已有固定译名的（如汉尼拔、哈米尔卡、汉诺）使用固定译名。
- **英文版**：同样参照原版英文的术语和文风。新增或修改文本时同步维护中英文，运行双语覆盖与格式检查，保留变量、概念链接、数值和格式标记。

### 美术

- **旗帜**：按原版纹章系统（`coat_of_arms`）制作，配色、比例、图案布局参照 1836 年前后各国旗帜和原版旗帜的风格。原版图案库中没有的纹章（塔尼特符号、日轮新月、棕榈树），自绘时与原版纹章的画风、线条粗细、着色方式保持一致。
- **图标**：利益集团、法律、日志、修正等图标沿用原版的图标风格和尺寸，优先直接复用原版图标。
- **事件插图**：优先使用原版已有的事件插图。

### 机制与数值

- 新法律、修正、日志的数值规模参照原版同类内容，避免明显过强或过弱。
- 新机制尽量借用原版已有的结构（如日志的进度条、事件的选项格式），让玩家不需要额外学习。

## 二、日志

### 日志 1：汉诺派与巴卡派

参考原版会议波兰的"白党和红党"日志的结构：使用一条双向进度条，随利益集团的政治力量、法律、战争状态和事件变化。这是前期主线：玩家先打下开局宣称的土地，凯旋之后两派之争爆发，最多持续 36 个月。

- **触发条件**：迦太基或其实际附庸拥有的黎波里塔尼亚或君士坦丁的任意土地；提前交给商站或行省后仍可触发。

- 进度从 0（汉诺派完全获胜）到 100（巴卡派完全获胜），初始为 **55**。
- 每月基础变化：巴卡派支持财产投票 +0.2、选举官僚 +0.15、贸易保护 +0.15；处于战争 +0.6；军队政治力量不低于 20% +0.2；有巴卡主义者或汉尼拔主义者领导的利益集团执政 +0.2；元首为上述意识形态 +0.3。

**治理介绍**：日志与附庸关系说明分别介绍商站和行省，并配有独立的船舶贸易徽记、官署卷册徽记。每个区域的事件正文、引语和两条成立路线都有特色文案。成立选项以商人、港口、税册、总督与地方秩序描述区域的未来，带有各地区特色；选项提示不再罗列法律名称。

**提示排版**：二十四个成立选项分别高亮新国家及宗主国名称，以可悬停的概念链接显示商站／行省类型，随后保留地区叙述，并强调 30%／50% 缴款与三个月交接期。恶名沿用原版选项效果显示，地块规则也只放在提示中。

## 三、决议

决议面板中有两个迦太基专属决议：

### 扩张商站

“迦太基的领土”中也提供逐个附庸的扩张按钮，如“扩张努米底亚商站”“扩张埃及行省”。配置了 24 个形式按钮，每个实际附庸只显示当前商站或行省对应的一个；点击只转交该附庸区域内、未处于殖民中的非首都土地。仅有殖民中土地时无法扩张；混有其他合格土地时只转交合格部分，殖民结束后才可移交原先排除的土地。原有批量扩张决议遵循相同规则。

- **出现条件**："迦太基的领土"已经开启
- **使用条件**：和平时期，在某个实际附庸的区域中拥有可转交的非首都州；不会交给同名外国或已经独立的原附庸
- **效果**：把直接管辖的非首都州转交给对应的既有商站或行省，覆盖上述十二个区域及全部十三个附庸国家。迦太基本土、西西里和现任首都不会被交出。

### 皈依伊斯兰教

- **出现条件**：本国信仰伊斯兰教的人口超过 40%（逊尼派、什叶派、伊巴德派合计），且国教还不是伊斯兰教
- **显示方式**：不弹提示，玩家需要自己进入决议面板才能看到；人口降到 40% 以下就会消失，之后满足条件可再次出现
- **描述**：为了在这片土地上存活，我们的执政官们只好带头改信周边的宗教……
- **效果**：参照原版国家集团的"强制改宗"，对本国使用：
  - 国教按当前脚本顺序选择：逊尼派人口占比不低于 20% 时改信逊尼派，否则什叶派不低于 20% 时改信什叶派，其余情况改信伊巴德派；元首和继承人随之改宗
  - 首都 5%、其他州 2% 的人口改宗
  - 修正"背弃塔尼特"：合法性 -10，持续 `normal_modifier_time`
  - 塔尼特信徒中产生激进分子

- 曲目播放后设置 3 次音乐请求的冷却，可被事件音乐正常打断，也可在音乐播放器中手动开关。
- 加权由国家条件计算，不会提高其他国家的抽取权重，也不会把商站当作迦太基本体；不替换主菜单音乐。
- 曲名已有简体中文和英文文本。Random（随机）模式忽略国家条件与权重，Least Played（最少播放）模式忽略权重；若希望体现迦太基的优先播放，请使用 Weighted 模式。

## 八、安装测试

1. 安装 [GitHub Desktop](https://desktop.github.com/)，登录自己的账号。
2. File → Clone repository，选择本仓库，本地路径选：
   `文档\Paradox Interactive\Victoria 3\mod\`
3. 打开游戏启动器 → Mods，把"迦太基重生"加入播放列表。
4. Steam 启动选项加上 `-debug_mode`，方便查看报错。
5. 以后有更新时，在 GitHub Desktop 点 **Fetch origin → Pull origin** 即可。

报错日志位置：`文档\Paradox Interactive\Victoria 3\logs\error.log`

测试音乐时，启用《迦太基》并把播放器切到 Weighted 模式；分别游玩迦太基与其他国家，使用 `Music.ListTracks` 比较权重。开局点播只在新游戏开始时尝试一次，读取存档不会再次调用开局点播。更新后需要完全退出并重新启动游戏。1.2.5 删除了公司、名品及专用建筑定义，旧档加载兼容性尚待游戏内验证。请分别选择简体中文和 English 检查界面、概念说明、历史地名和长文本排版。

数据与场景回归：`python -m unittest discover -s tests -v`。目前 120 项检查覆盖领土转交、原版领土交互兼容、共享冷却、逐个扩张及殖民中地区排除、十二处商站行省化与旧档日志补开、五年循环与赠款、总督制、路线分流、建筑完成等级、GDP 收入比例、公司建筑标识与关系贴图，以及中英文全部文本键、概念名称、替换引用、格式和数值对应，不能替代游戏内实测。新开局确认 3 艘护卫舰、1 级海军部门；和平时只取得君士坦丁或普罗旺斯即可测试领土日志。海军、开局经济干预和移民控制的历史设置针对新开局，已有存档的舰船数量与本国开局法律不回写。

## 九、发布到创意工坊

1. 确认本地是 `main` 分支的最新版本（不含测试事件）。
2. 启动游戏，在主菜单进入"模组"界面，找到"迦太基重生"，选择上传到 Steam 创意工坊。
3. 预览图使用模组根目录的 `thumbnail.png`（512×512）。
4. 上传完成后，在同一 Steam 工坊条目中提供[中文介绍](docs/workshop_description.txt)与[英文介绍](docs/workshop_description_english.txt)，无需另发一个英文模组。
5. 以后每次更新：先改 `.metadata/metadata.json` 里的版本号，再在游戏里重新上传，并在 Steam 页面写更新说明。
