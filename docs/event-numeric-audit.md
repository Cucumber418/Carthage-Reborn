# 迦太基重生：事件数值总表（审查版）

> **快照基准：** main 分支；本文件随主分支更新。  
> **统计范围：** 9 个 events 脚本文件，共 67 个事件定义。同步纳入这些事件直接调用的静态修正、脚本效果、日志目标、进度条和按钮。  
> **注意：** 本表记录脚本当前写入的值，不代表已通过游戏内平衡测试。PR 分支中的改动尚未合并到 main。

## 阅读说明

- 所有事件定义的弹窗持续时间均为 **3 天**（duration = 3）。
- normal_modifier_time、short_modifier_time、long_modifier_time、very_short_modifier_time、very_long_modifier_time、stupidly_long_modifier_time 是游戏/模组使用的时间常量。本表保留原常量名称，不猜测其天数。
- small_radicals、medium_radicals 是游戏的规模常量，不是固定人数或固定百分比。
- 乘数类修正按脚本原值记录；例如 0.05 通常表示 +5%，但 approval_add、legitimacy_base_add 等按对应游戏概念理解。
- “未写持续时间”表示事件调用 add_modifier 时没有明确写 days；不要把它误读成短期或永久，需以游戏实际行为确认。
- 事件经营收益和项目开支写入 country_tax_income_add / country_expenses_add，并在 add_modifier 时使用原版 money_amount_multiplier_* 按触发时 GDP 缩放，再通过 months 限时；金额显示为每周政府收入/政府支出。GDP 不会在修正持续期间逐周重新计算。

## 1. 全局触发频率与冷却

### 迦太基特色事件池

- 触发点：每半年一次的国家 pulse。
- 整个事件池的 chance_to_happen：**35%**。
- 事件池列出 16 个事件，每个权重均为 **10**。
- 如果 16 个事件全部符合条件，单次抽取时每个事件权重相同；实际会因国家条件、一次性标记和冷却而变化。
- crb_flavor.1、.5、.9、.15 使用变量标记防止重复触发。
- crb_flavor.9 还要求日期不早于 **1862.1.1**；crb_flavor.15 不早于 **1850.1.1**。
- 其他带 cooldown 的特色事件使用 normal_modifier_time。

### 汉诺派与巴卡派随机事件池

- 触发点：每月一次。
- 权重：空结果 120；8 个随机事件各 5；总权重 **160**。
- 若 8 个事件全部符合条件且冷却结束，月度出现任意一个事件的概率为 **40 / 160 = 25%**；每个单独事件权重为 5。
- 8 个事件均使用 normal_modifier_time 冷却。
- 单个事件的实际频率会受到事件条件与冷却影响。

## 5. 汉诺派与巴卡派：进度条、增长与按钮

### 进度条基础值

- 初始值：**55**。开局政府由地主与奉神者执政、三项初始法律偏向汉诺派，且汉诺派地主领袖在政府中；55 起点配合 +0.55/月的初段惯性，用来抵消这组结构性优势，而不是让巴卡派无条件领先。
- 最小值：**0**；最大值：**100**。
- 100：巴卡派胜利；0：汉诺派胜利。
- 日志开始后累计 **36 个月**仍未提前结束：触发三年期限结局；进度 ≥70 自动判巴卡派胜、≤30 自动判汉诺派胜，31–69 由玩家作最后抉择。
- 期限计数每月固定 +1，不再因进度离开 30–70 区间而归零。

### 独立的派系进度脚本效果

脚本另定义了四个可复用的进度变化效果（是否由其他事件/按钮调用，需结合具体调用处判断）：
- 巴卡派小幅增长：**+5**；中幅增长：**+8**。
- 汉诺派小幅增长：**-5**；中幅增长：**-8**。
- 手动让步按钮另外直接改变进度 **±10**，不要与上述随机效果混为一谈。

### 派系事件和让步按钮

- 随机事件池：每月总权重 160，其中空事件 120，8 个事件各 5。
- 每个随机事件基础 cooldown：normal_modifier_time。
- 让步按钮：向元老院让步使进度 **-10**；向公民大会让步使进度 **+10**。
- 两个让步按钮共用 **365 天**冷却。
- 向元老院让步时，军队、小市民、乡村民众支持度各 -2；向公民大会让步时，地主、工业家、奉神者支持度各 -2；修正持续 short_modifier_time。
- 年度君主制鼓动者概率：进度至少 50 时，以军队 clout ×100 为基础；进度至少 75 再乘 2；处于战争时再乘 1.5；最终最高 **50%**。每年检查一次。
- 汉诺派/巴卡派随机事件第 17 个（“国王”的流言）要求进度至少 **60**。

## 8. 第 N 次布匿战争

## 14. 当前数值中值得重点审查的地方

1. **派系惯性可能造成滚雪球。** 进度超过 95 后仅惯性就 +2.7/月；政治力量差改为乘 1.5，法律、战争和统治者条件仍会叠加。起点为 50，玩家连续支持一派时，目标是在三年期限内决出胜负。
2. **特色事件出现频率偏低。** 整体池每半年只有 35% 概率抽取，且部分事件有资格限制；事件中的资金效果均按 GDP 档位形成每周政府收入或政府支出，并持续指定期限，应在开局经济中测试其长期预算影响。
3. **盐碱地项目周期较长。** 要求 intensive_agriculture，治理期 10 年，启动后政府支出修正为 +1，完成只增加 8 可耕地；需要检查玩家是否愿意为此长期承担成本。
4. **复仇路线恶名较高。** 四阶段宣称分别为 +10、+15、+20、+25；创建行省仍额外增加 +10 或 +15。多阶段连续宣称会快速累积恶名，应视为一条高外交成本的扩张路线。
5. **战争按钮的效果与成本需要实测。** 动员公民是每场战争 +5 战争支持度；其费用修正使用 small 金额乘数和 very_short_modifier_time。元老院承诺提供两个 -0.25 的战争支持度下降乘数，并有 730 天冷却。
6. **皈依伊斯兰决议的宗教选择是优先级逻辑，不是最大人口逻辑。** 逊尼派只要达到 20% 就会优先于人口可能更高的什叶派/伊巴德派；这是明确的设计选择或待修复项。

- 进度条起点保持 55 以抵消汉诺派的开局结构优势；政治力量差乘数由 2.5 降为 1.5，避免 clout 差距单独决定胜负。
- 三年期限改为从日志启动起累计 36 个月。进度达到 70 或 30 时由领先派系自动获胜；仍处于 31–69 时触发玩家抉择事件。无论局势如何，派系斗争不会无限拖延。
- 随机事件基础月度触发率由 25% 提高至约 40%（无事件权重维持 120，8 个事件权重各由 5 提高至 10）；巴卡派选项增加进度 +8/+12，汉诺派选项仍为 -5/-8；让步按钮仍为每次 ±10、冷却 365 天。君主制鼓动者的触发门槛提高到进度 65，强势加权门槛提高到 85。
- 第一次布匿战争日志现在必须等派系斗争结论变量出现后，才会在对西西里持有者的外交博弈/战争中加入。
- 财政效果统一使用原版 country_tax_income_add / country_expenses_add + money_amount_multiplier_* + months：收入显示为每周政府收入，支出显示为每周政府支出；所有效果均按对应 GDP 档位计算并持续指定期限。

## 21. 第二轮派系斗争平衡修订

- **事件频率：** 派系斗争期间的随机事件权重由“无事件 120、每个事件 5”调整为“无事件 120、每个事件 10”。在八个事件均可用时，月度基础触发率由 25% 提高至 40%，平均约每 2.5 个月出现一次；每个事件原有的年度冷却保留，避免同一事件连续刷屏。
- **巴卡派事件增益：** 小幅支持由进度 +5 提高至 +8；中幅支持由 +8 提高至 +12。
- **汉诺派事件增益：** 保持小幅 -5、中幅 -8，不额外强化汉诺派，给玩家通过选择支持巴卡派来扭转局势的空间。
- **提示文本：** 巴卡派事件选项 tooltip 使用“小幅增加/大幅增加”，隐藏 +8/+12 的内部进度数值；实际进度变化不变。
- **财政措辞：** 事件资金效果统一显示为“+xxx 政府收入”或“+xxx 政府支出”，均为每周预算修正并持续指定期限；脚本底层仍使用原版预算修正，不改变结算机制。


## 22. 汉尼拔再临胜利路线校验修复

- **问题：** 汉诺派胜利效果此前只设置 `crb_hanno_victory`，没有清除可能残留的 `crb_barca_victory`；汉尼拔再临日志仅检查巴卡派标记和派系斗争结束标记，开场事件也没有独立触发条件校验。残留标记可能导致汉诺派胜利后仍触发巴卡派专属宣称事件。
- **互斥胜利标记：** 巴卡派胜利效果清除汉诺派胜利标记；汉诺派胜利效果清除巴卡派胜利标记。派系斗争日志开始时也清理两种旧标记。
- **日志条件：** 汉尼拔再临的显示条件、激活条件和开场效果均要求巴卡派胜利，且明确排除汉诺派胜利；增加防御性失效结局，避免日志在错误胜利标记下继续推进。
- **事件条件：** `crb_hannibal.0` 开场事件增加独立校验，必须是迦太基、巴卡派胜利、派系斗争已结束、汉诺派未胜利且汉尼拔路线尚未结算，才可发放领土宣称。

- **胜利标记时序：** 汉诺派在派系斗争结局结算时立即写入胜利标记并清除巴卡派标记，不再等待玩家关闭“汉诺派获胜”后续弹窗；避免结局与弹窗选择之间的短暂窗口让旧巴卡派标记误触发汉尼拔再临。

## 23. 原版财政写法与北非战争事件

- **收入/支出计算：** 继续采用原版事件常见写法：静态修正以 `country_tax_income_add = 1` 或 `country_expenses_add = 1` 为基数，在 `add_modifier` 时传入 `money_amount_multiplier_*`，并用 `months` 限定期限。原版倍数从修正生效时的 `root.gdp` 计算并取整，因此金额随当时经济体量变化，不是固定周金额；但在持续期内也不会每周重新计算。
- **玩家可见措辞：** `country_tax_income_add` 显示为“政府收入”，`country_expenses_add` 显示为“政府支出”；具体金额由原版 GDP 倍数计算，玩家看到的是每周金额与持续期限。
- **支出注释纠正：** 教育拨款、染坊补贴、农书翻译、战象阅兵、沉船博物馆与梅尔卡特盛典均通过持续期内每周生效的预算修正结算，不是一次性付款；事件脚本注释已按实际机制修正。
- **新事件 crb_flavor.17「高卢人？」：** 参照原版战斗事件结构，通过 `on_battle_won`、`on_battle_lost`、`on_empty_battle_won`、`on_empty_battle_lost` 的 `on_actions` 子调用，以 `events = { crb_flavor.17 }` 触发；事件自身使用 `fire_only_once = yes`，并检查 ROOT 为迦太基、`scope:enemy_country` 为法国、`scope:state` 属于原版 `03_north_africa.txt`。只触发一次，不进入半年随机事件池。
- **战斗奖励：** 事件给予 `crb_flavor_gallic_legacy`，部队击杀率 `unit_kill_rate_add = 0.1`（+10%），持续 `normal_modifier_time`。

## 24. 原版战斗事件触发方式校正

- **原版对照：** 原版 `on_battle_ended` 定义为空；战斗胜利事件通过 `on_battle_won` 的 `events = { event_id }` 调用。原版德克萨斯事件 `texan_war_of_independence.3` 使用 `fire_only_once = yes`，并在事件自身的 `trigger` 中读取 `scope:enemy_country` 等战斗作用域。
- **本模组修正：** 不再使用 `on_battle_ended`。改为从 `on_battle_won`、`on_battle_lost`、`on_empty_battle_won`、`on_empty_battle_lost` 调用同一个子 on_action，由其 `events` 列表触发「高卢人？」。因此首次符合条件的陆战结束后，无论胜负均可触发。
- **地区清单：** 北非触发器严格采用原版 `state_regions/03_north_africa.txt` 的 31 个地区，删除了不存在的 `STATE_LOWER_EGYPT`。
- **巴卡派提示：** 小幅/大幅支持的内部进度仍分别为 +8/+12；玩家 tooltip 改为“小幅增加/大幅增加”，不再显示具体数值。

## 25. 事件资金效果统一为限时每周政府收入/支出

- **统一规则：** 所有事件资金效果均使用限时 `add_modifier`，不使用一次性 `add_treasury`。
- **政府收入：** 静态修正使用 `country_tax_income_add = 1`，事件添加时使用原版 `money_amount_multiplier_*` 并通过 `months` 设置期限；游戏内显示为每周“+xxx 政府收入”。
- **政府支出：** 静态修正使用 `country_expenses_add = 1`，事件添加时使用原版 `money_amount_multiplier_*` 并通过 `months` 设置期限；游戏内显示为每周“+xxx 政府支出”。
- **老兵赏金：** 使用 GDP small 档每周政府支出，持续 12 个月；不再一次性扣除国库。
- **简体中文属性名：** `country_tax_income_add` 统一显示为“政府收入”，`country_expenses_add` 统一显示为“政府支出”，不再使用“额外收入”措辞。
- **金额与期限：** 金额按修正添加时的 GDP 计算；每周结算至修正到期后自动停止。各事件的 `months` 按其具体项目周期设置。
